# Definition of Ready — 구현 시작 조건

이 문서는 “추측 없이 안전한 단위로 구현을 시작할 수 있는가”만 판정한다. 행동·승인 권한은 [AGENTS.md](../AGENTS.md), 구현 종료는 [Done](DEFINITION_OF_DONE.md)를 따른다.

## 기록 방법
Issue 또는 작업 문서에 아래 정보를 기록한다. 기존 문서 링크로 대체할 수 있다. 모든 적용 항목이 충족되면 Ready다. 해당 없음은 이유를 적고, 미정·차단은 담당자와 해결할 질문을 적는다.

- [ ] 목적과 사용자 시나리오: 누구의 어떤 문제를 해결하는가?
- [ ] Scope / Out of Scope: 포함할 행동과 이번에 하지 않을 행동은 무엇인가?
- [ ] Acceptance Criteria: 정상·주요 실패·경계 상황의 관찰 가능한 기대 결과가 있는가?
- [ ] 핵심 정책과 도메인 불변조건: 결정된 내용과 권위 있는 문서/구현 위치가 있는가?
- [ ] 기존 구조·유사 코드·데이터·권한·UI 영향을 확인했는가?
- [ ] 새 영역은 적절한 Reference 조사를 마치고 채택/배제 이유를 남겼는가?
- [ ] API/모듈의 입력·출력·오류·권한·부작용과 변경 시 호환성을 합의했는가?
- [ ] 작업을 독립적으로 검증·리뷰·철회 가능한 단위로 나누고 선행 의존성을 확인했는가?
- [ ] Feature Owner와 Reviewer, Issue, 예정 브랜치, 변경 모듈, 수정 제외 영역이 정해졌는가?
- [ ] 다른 세 팀원의 진행 작업과 공유 영역 충돌 가능성을 확인했는가?
- [ ] 검증 환경·명령·데이터와 필요한 CI가 준비되었거나 구현 범위에 명시되었는가?
- [ ] 보안·데이터 손실·운영 영향에 맞는 검증과 복구 방향이 있는가?
- [ ] Level 3 선택은 결정서와 PO 승인 근거가 있는가?

## 준비되지 않은 경우
제품 정책·권한·데이터 의미를 추측해 구현하지 않는다. 부족한 항목과 영향 범위를 밝히고, 조사·계약 합의·검증 환경 준비 등 독립적인 선행 작업으로 분리한다. 작은 수정은 Issue의 짧은 설명으로 충족할 수 있으며 모든 항목을 장문으로 작성할 필요는 없다.

## Acceptance Criteria 예시
“동일한 실행의 포인트를 한 번만 지급한다”는 정책이 승인되었다면:
- 첫 유효 요청은 지급 결과를 저장하고 표시한다.
- 동일 요청 재시도와 동시 요청에도 누적 지급은 한 번이다.
- 타인의 실행에는 접근이 거부되고 잔액은 변하지 않는다.
- 저장 실패 후 재시도해도 중복 지급 또는 미기록 지급이 생기지 않는다.

예시는 실제 제품 정책을 대신하지 않는다.
