# PROOVIT 개발 지침 파일 안내

이 세트는 2026-09-12에 이전 대화에서 확정한 Engineering Constitution v1.0의 45개 조항과 개발 루프를 실행 문서로 분리한 것이다. 특정 기술 스택·GitHub 저장소·CI 명령은 아직 주어지지 않았으므로 임의로 확정하지 않았다.

## 문서 책임
- [AGENTS.md](../AGENTS.md): 공통 원칙, 공식 기준, AI 결정 권한, PO 소통.
- [.cursor/rules](../.cursor/rules): 주제별 실행 방법. 00은 항상 적용하는 진입점이며 01~08은 작업별로 읽는다. Cursor 파일은 Markdown 본문에 메타데이터를 붙인 .mdc 형식이다.
- [PR 템플릿](../.github/pull_request_template.md): 변경·검증·리뷰·출시 근거를 수집하는 양식.
- [Ready](DEFINITION_OF_READY.md): 구현 시작 여부.
- [Done](DEFINITION_OF_DONE.md): 구현·병합·출시 상태 판정.
- [결정 템플릿](templates/ENGINEERING_DECISION.md): 대안·trade-off·실제 결정의 보존.
- [리뷰 체크리스트](CODE_REVIEW_CHECKLIST.md): 독립 Reviewer의 결함 탐색과 결과 보고.

규칙 문구를 여러 문서에 복사해 유지하지 않는다. 기준 변경은 해당 책임 문서를 수정하고 다른 문서는 링크와 증거 수집 항목만 맞춘다. 상세 규칙은 도구의 자동 선택에만 의존하지 않고 AGENTS.md의 문서 선택 절차로 직접 읽는다.

## 저장소에 적용하기
1. 이 파일 구조를 프로젝트 루트에 둔다. 기존 파일이 있다면 내용을 검토·통합한다.
2. 네 팀원이 용어·역할·승인 기준을 함께 확인하고 지침 PR을 검토한다.
3. 실제 프로젝트의 런타임·설치/개발/검증 명령·환경변수 템플릿과 필요한 공식 문서를 기록한다.
4. GitHub의 CI와 main 보호 설정은 [프로젝트 전체 병합 기준](decisions/2026-09-21-project-merge-policy.md)에 맞춰 확인한다. 팀원 Approve는 선택 사항이다. 이 파일 세트는 GitHub 설정이나 CI 워크플로를 자동 변경하지 않는다.
5. 첫 기능 Issue에 Ready를 적용하고 작은 PR부터 개발 루프를 운영한다.
