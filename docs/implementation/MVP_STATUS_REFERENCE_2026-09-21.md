# PROOVIT MVP 구현 현황 및 남은 작업

> **팀 공유용 참고 문서 · 2026-09-21 기준**
>
> 특정 시점의 코드·PR·검증 상태를 정리한 문서입니다. 공식 제품 정책, 병합 규칙, 배포 승인 또는 작업 지시를 새로 정하지 않습니다. 이후 진행 상황은 아래 PR과 최신 저장소 문서에서 확인하세요.

## 한눈에 보는 현재 상태

**MVP 핵심 7개 기능의 코드가 준비됐고, main 통합과 실제 서비스 검증이 남아 있습니다.**

- 팀원 통합본은 PR #9를 통해 main에 반영됐습니다.
- 정아 담당 상세·카메라·사진 제출·점수 연결은 PR #8·#10에 올라와 있으며 아직 main에 병합되지 않았습니다.
- 자동 테스트는 통과했지만 실제 Supabase 연결과 갤럭시·아이폰 검증, 배포까지 완료된 상태는 아닙니다.
- 따라서 **코드 구현 완료 ≠ main 병합 완료 ≠ 실제 서비스 출시 완료**입니다.

### 미션 콘텐츠와 인증 방식

- PDF를 기반으로 31일 콘텐츠를 구조화했고, Day 18 PIVOT은 ‘해결책 방향 조정’으로 명확히 했습니다.
- 제출 항목·완료 기준과 개인정보 마스킹 안내, 카메라 전용 인증 문구를 반영했습니다.
- UI는 앱 내 새 촬영만 제공하며 사진첩·일반 파일 업로드 버튼은 제공하지 않습니다.
- 사진 인증은 소유권·해금/마감·파일 형식·크기·저장 성공 등을 확인하는 **기술 검증 후 자동 인정**입니다. AI가 사진 내용이나 수행 진위를 심사하는 기능은 아닙니다.
- 서버 점수는 당일100점 / 다음 날70점 / 이후40점이며, 미션별 유효 제출 점수는 한 번만 지급합니다. 해금 전·전체 마감 후에는 제출할 수 없습니다.

## 3. 검증 완료와 미검증 구분

- 타입 검사, lint, 포맷 검사 및 프로덕션 빌드 통과.

- 브라우저 E2E의 OAuth·Storage·카메라는 테스트용 대역입니다. 실제 Google 로그인·Supabase 사진 저장·물리 카메라를 검증한 것은 아닙니다.
- PR #8 Bugbot은 코드·테스트를 독립 검토해 재현 가능한 결함을 발견하지 못했습니다. 해당 리뷰에서 빌드/E2E를 새로 실행하거나 PDF 원문을 재대조하지는 않았습니다.
- 갤럭시 실제 브라우저, 아이폰 Safari의 권한·회전·백그라운드 복귀·촬영·이탈은 미검증입니다.
- PR #10은 독립 리뷰와 main 통합 후 최종 검증이 남아 있습니다.

## 4. 남은 작업 — 권장 진행 순서

### 1단계: 병합 규칙 문서 정합성 정리

- PO는 전체 프로젝트에서 팀원 GitHub Approve를 필수로 요구하지 않도록 변경을 요청했습니다.
- 기준 시점의 공통 규칙에는 이전 요건이 남아 있으며, 실제 규칙 파일 수정·커밋은 아직 하지 않았습니다.
- 공통 규칙과 관련 문서를 별도 변경으로 일관되게 정리해야 합니다. **이 참고 문서만으로 병합 규칙을 변경하거나 예외를 승인하지 않습니다.**

### 2단계: 우리 작업을 main에 통합

1. PR #8의 최종 리뷰·CI·적용되는 병합 조건 확인 후 병합.
2. PR #10의 base를 main으로 변경.
3. 필요시 최신 main 반영과 콘텐츠·테스트 충돌 해결.
4. PR #10 독립 리뷰, 차단 지적 수정, 최종 CI 확인 후 병합 승인에 따라 진행.

### 3단계: 실제 Supabase 설정·데이터 반영

- 실제 환경을 확인하고 승인된 대상에 새 DB 구조와 비공개 사진 저장소를 적용합니다.
- 실제 챌린지에31일 콘텐츠를 등록합니다. 개발용 seed를 운영 데이터에 그대로 덮어쓰지 않습니다.
- Google OAuth, callback 주소, 서버 전용 설정을 확인합니다. 비밀 키는 Git이나 공유 문서에 넣지 않습니다.
- 실제 로그인 → 참가 → 상세 → 사진 저장 → 점수 반영 → 재접속 흐름을 확인합니다.
- 새 migration과 운영 데이터 적용은 아직 실행하지 않았습니다. 적용 전에 환경·대상·권한을 별도로 확인해야 합니다.

### 4단계: Vercel 배포와 실제 휴대폰 검증

- 저장소를 Vercel에 연결하고 HTTPS 미리보기 주소를 준비합니다.
- 갤럭시와 아이폰에서 권한 허용/거부, 촬영·재촬영·제출, 이탈 시 카메라 종료를 확인합니다.
- 사진 속 작은 글씨의 가독성, 화면 넘침, 오류 안내와 다시 시도를 확인합니다.
- Vercel 연결·배포는 아직 진행하지 않았습니다.

### 5단계: 출시 전 운영 준비

- 사진 보존기간 종료 및 실패 객체 정리 명령은 작성됐지만, 자동 실행 스케줄은 미설정입니다.
- 삭제 스케줄·실패 알림·대응 담당자를 정하고 실제 환경에서 삭제·재시도·복구를 확인합니다.
- 문제 발생 시 새 제출 중단, 이전 앱 버전 복귀, 인정·점수 기록 보존 절차를 확인합니다.

## 5. 이번 핵심 7개 기능과 구분할 사항

- AI 사진 내용 심사, 랭킹 확정·보상/금전 지급은 이번 상세·카메라·점수 연결 변경에 포함되지 않았습니다. 더 넓은 제품 범위에 포함할지는 별도 계획으로 관리합니다.
- 마이페이지는 계정 표시·로그아웃이 있으며, 상세 참가·진행 내역은 아직 안내 상태입니다. 핵심 7개 기능의 완료와 마이페이지 전체 완성을 혼동하지 않습니다.
- 저장소 업로드, PR 병합, DB 적용, 웹 배포는 각각 별도 작업입니다. 어느 하나가 완료됐다고 다른 작업까지 완료된 것으로 표시하지 않습니다.

## 요약

**큰 기능을 새로 만드는 단계보다는, 준비된 코드를 통합하고 실제 환경에서 검증하는 단계입니다.**

다음 순서는 **규칙 문서 정리 → PR #8 병합 → PR #10 main 기준 재검증·리뷰 → 실제 Supabase 연결 → HTTPS 배포·휴대폰 검증 → 운영 준비**입니다.

문서 갱신 시에는 기준 날짜·커밋·PR 상태와 검증 근거를 함께 갱신하고, 계획을 완료 사실로 바꾸지 않습니다.
