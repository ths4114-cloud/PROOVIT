# Definition of Done — 완료 증거와 단계

이 문서는 결과를 어떤 상태로 보고할지 정한다. PR은 [템플릿](../.github/pull_request_template.md)에 아래 증거를 연결한다. 검증 방법은 [테스트 규칙](../.cursor/rules/05-testing-quality.mdc), 검수 질문은 [리뷰 체크리스트](CODE_REVIEW_CHECKLIST.md)가 소유한다.

## 공통 판정
각 항목은 통과 / 실패 / 미실행 / 해당 없음으로 표시한다. 해당 없음에는 이유를 남긴다. 명령·환경·대상 커밋·결과 또는 결과 링크를 기록한다. 필수 항목 실패·미실행은 완료가 아니다. 도구나 환경이 없으면 그 제약을 그대로 보고한다.

## 1. 구현 완료 — 리뷰 가능한 상태
- [ ] 목적과 Acceptance Criteria를 충족하고 현재 범위 밖 변경이 섞이지 않았다.
- [ ] 도메인 불변조건·단일 정책 구현·계약/호환성을 확인했다.
- [ ] 해당 타입 검사·lint·build와 관련 단위/통합/E2E/회귀 검증을 통과했다.
- [ ] 핵심 정책의 자동 테스트 및 관련 오류·권한·중복·동시성·부분 실패 검증이 있다.
- [ ] 해당 loading/empty/error/retry 상태와 모바일/주요 UI를 확인했다.
- [ ] 보안·개인정보·비밀정보·데이터 무결성 영향을 검증했다.
- [ ] 필요한 migration·설정·운영 신호·복구 절차를 준비했다.
- [ ] 변경된 정책/도메인/아키텍처/DB/API/용어 문서를 코드와 함께 갱신했다.
- [ ] 대체된 코드·불필요 의존성을 확인하고 남은 부채는 책임자·기한/재검토 조건과 함께 기록했다.

## 2. 병합 가능 — PR Gate 통과
- [ ] 독립된 Reviewer가 검토하고 차단 이슈를 해결했다.
- [ ] 다른 팀원 한 명 이상의 사람 리뷰가 기록되었다. 중요한 변경은 필요한 전문 검토와 PO 결정도 있다.
- [ ] 최신 PR 변경에 대한 모든 필수 CI 검사가 통과했다.
- [ ] 충돌과 선행 PR 의존성이 해결되었고 최종 변경의 회귀 위험을 확인했다.
- [ ] PR 설명·결정/승인 근거·미해결 위험이 실제 diff와 일치한다.

문서만으로 CI·브랜치 보호가 설정되지는 않는다. 아직 없는 필수 검사는 “미설정”으로 기록하고 구성 후 통과해야 한다. AI 자기 점검은 독립 리뷰나 사람 승인을 대신하지 않는다.

## 3. 병합 완료 / 출시 준비
- [ ] 병합 결과와 커밋을 확인했다.
- [ ] 스테이징에서 배포 대상의 주요 흐름·설정·migration을 확인했다.
- [ ] 배포 담당자·순서·성공/중단 조건·관측 위치·복구 절차가 있다.
- [ ] 위험에 맞는 rollback/restore 검증과 필요한 배포 승인이 있다.

## 4. 출시 완료
- [ ] 운영 반영 버전과 결과를 확인했다.
- [ ] 배포 후 핵심 흐름·오류·지표를 확인하고 관측 담당자/기간을 기록했다.
- [ ] 발생 문제와 후속 작업을 기록하고 필요한 대응을 수행했다.

개발만 요청받았다면 “구현 완료, 병합/출시 미진행”처럼 범위와 상태를 보고한다. Done을 충족하기 위해 요청되지 않은 운영 배포를 임의로 실행하지 않는다.
